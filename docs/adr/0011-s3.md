# 0011. S3 with a small signed-request client, settings from ~/.aws

- Status: Accepted
- Date: 2026-11-15

## Context

S3 is in the base scope, and "S3" in practice means AWS plus many
compatible services (MinIO, Cloudflare R2, Backblaze B2, Wasabi, Ceph). A
file manager must show keys exactly as they are stored, including names
with `%`, `#`, spaces or non-ASCII characters, and must not mangle keys
written by other tools.

Libraries considered:

- the AWS SDK: very large, and pulls a second HTTP stack and aws-lc
  (cmake, C toolchain), which complicates the static agent build;
- `object_store`: good, but its `Path` type re-encodes some characters
  and cannot name folder marker objects (`name/`), so keys created by
  other tools would not round-trip.

## Decision

- `nmc-s3` signs requests itself (Signature Version 4, about 100 lines,
  tested against the example in the AWS documentation) and sends them
  with the `reqwest` client already used for WebDAV (ADR 0010). It uses
  `ListObjectsV2`, `HEAD`/`GET` with ranges, `PUT`, multipart uploads in
  8 MiB parts, `CopyObject` and `DELETE`. Payloads are sent as
  `UNSIGNED-PAYLOAD`, so uploads stream without hashing first.
- Locations are `s3://bucket/key` or `s3://profile@bucket/key`. Keys,
  region and endpoint come from the AWS environment variables
  (`AWS_ACCESS_KEY_ID`, `AWS_REGION`, `AWS_ENDPOINT_URL`, ...) and the
  `~/.aws/credentials` and `~/.aws/config` files, like the AWS CLI. A
  profile in the location uses that profile only, so each service can
  have its own `endpoint_url`. Without keys, requests are anonymous.
- Custom endpoints use path-style requests (`endpoint/bucket/key`), which
  all compatible servers accept; AWS uses virtual hosts.
- Keys are shown as a tree split at `/`. Creating a folder stores an empty
  `name/` marker object. Renaming a folder copies every object, then
  deletes the originals: slow for large folders and not atomic, but an
  interruption never loses data.

## Consequences

- Credentials from instance metadata, SSO or `credential_process` are not
  supported yet; they can be added to `settings` without touching the
  provider.
- No resume for uploads and no setting of modification times (S3 cannot
  do either). `CopyObject` is limited to 5 GB per object.
- Tests run against `s3s-fs`, an S3 server that checks signatures. It
  keeps folder markers as directories that its listings do not show, so
  empty-folder visibility is not covered by the integration tests.

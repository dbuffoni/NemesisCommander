# 0012. SMB with the pure-Rust smb2 client

- Status: Accepted
- Date: 2026-11-15

## Context

SMB (Windows shares, Samba, NAS devices) is in the base scope. The usual
choice on Linux is `libsmbclient` from Samba, but it is a large C library
with many dependencies: it would break the "one binary, cross-compiled
everywhere" goal and is GPL-3, which matters while the license is open.

## Decision

- `sc-smb` uses `smb2`, a pure-Rust SMB 2/3 client (dialects 2.0.2 to
  3.1.1, NTLM, signing, encryption, compression, DFS). Its sibling crate
  `smb` was also considered; `smb2` has the simpler streaming API
  (positioned readers, pipelined writers, server-side copy).
- Locations are `smb://[user@]host[:port]/share/path`. `smb://host/` lists
  the shares (without administrative `$` shares). One connection per
  server; shares are connected on first use.
- Logins come from `.netrc` like WebDAV (the netrc reader moved to
  `sc_vfs::netrc` for both). No user means a guest session.
- Capabilities: resumable writes (positioned writer), atomic replacing
  rename, modification time, server-side copy within a share. POSIX
  permissions and symlinks are not exposed.
- Tests run against a real Samba started by `scripts/smb-test-server.sh`
  (CI on Linux does this; elsewhere the tests skip without a server).

## Consequences

- Kerberos sign-in is not available yet (`smb2` does NTLM); it can be
  added when the library offers it.
- Listings are read whole before they are shown; very large folders take
  a moment before the first rows appear.
